# 豫膳煌 · 选址评分卡

给加盟商 / 客户在外面看点位时用的自助评测工具。填 10 项，30 秒出分，给出结论、下一步动作和现场待核实清单。

纯前端静态站，没有后端，数据只存在填表人自己的手机/电脑浏览器里。

- 线上地址：https://guanzucheng.github.io/site-evaluator/
- 姊妹工具（门店进销存日报）：https://guanzucheng.github.io/

## 怎么用

1. 打开链接，按 1 → 2 → 3 三组把信息填完。拿不准的项选「不确定」，不会因为选不确定就故意扣分，但会在结论里提示你去现场补什么。
2. 点「出评分和结论」，得到总分、等级、一句话结论、6 个维度条、建议和待核实清单。
3. 想看几个点位对比：点「保存这个点位」，回到「我的点位」按分数从高到低查看。
4. 要发给总部或存档：点「复制结论」，粘到微信里；或者直接截屏结果卡（手机一屏放得下分数、结论和建议）。

## 评分口径

总分 100，六个维度：

| 维度 | 分值 | 说明 |
|---|---|---|
| 客流 | 30 | 按早 6:30–11:00 门口经过人次分档 |
| 周边业态 | 20 | 社区/学校/商圈/写字楼等，按最强业态 + 次强业态加权 |
| 租金压力 | 20 | 租售比占 70%，每平米单价占 30% |
| 竞品环境 | 10 | 500 米内同类门店数量 |
| 门店硬件 | 10 | 排烟、上下水、明火、三相电、外摆 |
| 可见度 | 10 | 门头在主街/次街/巷内/商场内 |

等级：A ≥80 建议推进 / B 65–79 可谈先补短板 / C 50–64 谨慎 / D <50 不建议 / X 关键信息缺失，不给结论。

三条红线会直接把等级往下压一档（最多压两档）：

1. 既没排烟也没明火（须先解决抽排或改电加热）
2. 没有上下水（改造要砸地）
3. 租金单价超过店型基准 1.5 倍且客流偏弱

估算月营业额 = 客流档位中位数 × 进店率 × 客单价 × 30，误差约 ±30%，只用来感知租售比，不参与打分。

## 地图（可选）

不配 Key 也能用，地址手打即可。配了 Key 之后可以搜索地址、地图选点、自动统计 800 米内小区/学校/写字楼/商场/胡辣汤门店数量，并自动勾选周边业态。

点右上角「设置」填 Key，Key 只存在本机浏览器，不进代码、不上传。

- 高德：console.amap.com/dev/key/app → 创建应用 → 添加 Key（服务平台选 **Web端(JS API)**），域名白名单填 `guanzucheng.github.io`。会给你 Key 和安全密钥 jscode 两串，都填上。
- 百度（可选）：lbsyun.baidu.com/apiconsole/key → 应用类型选 **浏览器端**，Referer 白名单填 `guanzucheng.github.io`。

常见报错：

- `INVALID_USER_DOMAIN`：域名没加白名单，或本地用 file:// 打开（本地预览要改用 http 服务）。
- 地图空白但地址能搜：安全密钥 jscode 没填。
- 百度接口 302 / 无结果：AK 类型选错，必须是浏览器端。

## 本地打开

直接双击 `index.html` 能看界面，但地图和高德接口会被 file:// 限制。要看完整效果：

```bash
python3 -m http.server 8080
# 浏览器打开 http://localhost:8080
```

## 改口径

评分权重、店型基准租金、各档分数都在 `app.js` 顶部常量里（`TYPES` / `TRAFFIC` / `BIZ` / `COMP` / `VIS` / `COND`），改完 push 到 main 会自动重新部署。
